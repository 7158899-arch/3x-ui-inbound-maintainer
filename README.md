# 3x-ui Inbound Maintainer

Интерактивная утилита для безопасного обслуживания **локальных Inbound** панели **3x-ui v3.11.0** через штатный API.

## Возможности

- Автоматически находит порт, `webBasePath` и HTTPS панели с помощью `/usr/local/x-ui/x-ui setting -show`.
- Подключается к API по `127.0.0.1`. Если настроен `webDomain`, определяет его из локальной SQLite **только для чтения** и передаёт через HTTP `Host`.
- Создаёт/перевыпускает выделенный технический API-токен `local-flag-rename`; **значение токена не записывается в код и логи**.
- Отбирает только локальные подключения (`nodeId` отсутствует или `null`); удалённые узлы не обновляет.
- Даёт **независимо пропустить** замену эмодзи-флагов в начале `remark` и обновление публичного IPv4 в `shareAddr`.
- Обновляет IPv4 только при стратегии `shareAddrStrategy = "custom"`. **Саму стратегию не меняет**; домены и IPv6 не переписывает.
- Показывает старые и новые значения и запрашивает подтверждения.
- Создаёт резервные копии конфигураций в `/root/xui-local-backups/` с ограниченными правами. Эти копии **содержат секреты клиентов** и не должны попадать в Git.
- Поддерживает `--dry-run`, `--debug`, `--debug-file` и `--host`.

> Поддерживается и проверялась версия **3x-ui v3.11.0**. Скрипт требует root для запуска штатного CLI. Обновление Inbound через API может кратковременно влиять на активные соединения Xray.

## Быстрая установка после смены сервера

На сервере после установки и первоначальной настройки поддерживаемой версии 3x-ui:

```bash
curl -fsSL 'https://raw.githubusercontent.com/7158899-arch/3x-ui-inbound-maintainer/main/xui-local-update.py' \
  -o /root/xui-local-update.py
chmod 700 /root/xui-local-update.py
python3 -m py_compile /root/xui-local-update.py
python3 /root/xui-local-update.py --debug --dry-run
```

Для обычного запуска:

```bash
python3 /root/xui-local-update.py
```

Если `webDomain` автоматически не определён, можно указать его **без протокола и пути**:

```bash
python3 /root/xui-local-update.py --host panel.example.com --debug --dry-run
```

Для повторяемого развёртывания лучше использовать опубликованный тег или конкретный commit SHA вместо `main` в ссылке `raw.githubusercontent.com`, проверяя скачанный код перед запуском с правами root. **Не запускайте `curl | bash`.**

**Совместимость:** скрипт специально проверяет версию `3.11.0`. Установка 3x-ui через `master/install.sh` может поставить более новую версию — тогда скрипт намеренно откажется работать до проверки совместимости.

## Безопасность и приватность

**В репозитории должны храниться только исходный Python-скрипт, README, `.gitignore` и другие явно проверенные публичные файлы.** Никогда не публикуйте:

- Логи с настоящими доменами, адресами и путями вашей панели;
- JSON-резервные копии Inbound (клиентские UUID, ключи и параметры подключений);
- Файлы `.db`, `.env`, приватные ключи и токены;
- Скриншоты настроек реального сервера и конфигурации подписок.

В режиме `--debug` скрипт может показывать реальный Listen Domain; `--debug-file` сохраняет эту диагностику локально. Сервисы `api.ipify.org` и `ipv4.icanhazip.com` используются для определения публичного IPv4 **только при выборе операции IPv4**.

**Важно:** публичная публикация исходников не раскрывает параметры ваших серверов, пока вы не добавляете их в коммиты или логи. Перед первым `git push` проверьте список отслеживаемых файлов командой `git ls-files`.
